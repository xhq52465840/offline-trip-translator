# 三语互译与界面国际化改造计划（仅计划，未实施）

> 2026-10-14 · 状态：**待 r5 完成后开始**。r5（`docs/MAC_AGENT_TASKS.md` 文首清单）仍然有效，先跑完，本计划各阶段再接着做。
> 目标：
> - (A) 中文、印尼语、英语任意两种之间都能互译；对话里双方**各自**选自己的语言，每一方都可以是三种中的任意一种。
> - (B) 界面全量中文 / 英文：默认跟随系统语言，App 内可单独切换语言；App Store 材料也要出英文版。
> 原则：每个阶段改动小、能单独验证；Linux 上保持 `swift test` 全绿，UI 文件过 `swiftc -parse`；Mac 每阶段跑 UI 测试并截图。

## 0. 现状（改造起点）
- `Lang.tourist = "zh-Hans"` 写死「我方 = 中文」，`Conversation.theirLanguage` 只能是 `id` 或 `en`；`LanguageGuess` 只区分 id 和 en。
- 理解提示词（`Understander`）的 few-shot 全部是「对方印尼语 → 中文输出」，`Validator` 按中文输出校验金额（如「3万」）。
- `AmountParser` 认印尼盾写法（rb/jt/ribu/Rp），`AmountAnnotator.annotateChinese` 只对中文加注；FX 的目标币种按**系统语言**选（zh → CNY，其他 → USD）。
- 常用句 `Phrase(zh, id:, en:)` 以中文为键；场景名称、副标题、`Copy.*` 都是硬编码中文。
- Apple Translation 用到的语言对：id→zh、en→zh、zh→id、zh→en。语音识别 locale 有 zh-CN、id-ID、en-US。
- LoRA s400 只训练过「id/口语 → 中文理解」和回放数据（含 FLORES dev 的印→中、印→英）。

## 1. 受影响的部分
| 部分 | 现在 | 改造后 |
|---|---|---|
| 语言模型 | 我方固定中文，对方 id/en | `Party{me, partner}` 各带 `lang ∈ {zh-Hans, id, en}`，允许双方同语（同语时直接显示原文，不翻译） |
| 对话界面 | 顶栏「对方说印尼语」 | 顶栏两个语言选择：「我说 ▾ / 对方说 ▾」，交换按钮 ⇄；面对面模式两半屏各自有语言按钮，按住说话用该方的语音 locale |
| 常用句 / 场景 | 中文为键，附 id/en | 三语齐全的 `PhraseText{zh,id,en}`，按「我方语言显示、对方语言出示」；英文版场景文案需重写（不能直译中文语境，如「按 App 价」） |
| Apple Translation | 4 个方向 | 6 个方向（zh↔id、en↔id、zh↔en）；离线语言包按「我方 + 对方」两种语言检查并引导下载；`Readiness` 改为按语言对 |
| 语音 | 3 个 locale | 不变，但要按「说话方」选；面对面两半屏各一个；不支持时显示按语言区分的提示 |
| 金额 | 只认印尼盾写法、只在中文里加注 | ① 英文金额解析（`IDR 50k`、`50 thousand rupiah`、`1.5 million`、`$20`、`20 dollars`）；② 加注目标改为「**查看者的语言**」：中文用户 → ¥，英文用户 → $，印尼语用户 → Rp（反向把 ¥/$ 换成 Rp）；③ `annotateEnglish` 与 `annotateChinese` 用同一套白名单规则（只给与原文解析值相等的数字加注） |
| 提示词 | id → zh 理解 | 理解输出用「**查看者语言**」，所以提示词要参数化 `{src_lang, tgt_lang}`；few-shot 按目标语言选（zh 或 en）；`Validator` 增加英文金额格式校验（如 `IDR 30,000` / `30k rupiah`）。印尼语作为目标语言时只做直译（Apple Translation），不做理解 |
| LoRA 数据 | 场景 id→zh + 回放 | 新增 id→en 理解场景，以及 zh↔en、en↔id 回放（见 §4） |
| 评测 | App 60 条（id→zh）+ 公开集 id→zh、id→en | FLORES devtest 六个方向 + App 格式（id→zh、id→en 两套），**按方向**判定是否采用（见 §5） |
| 界面国际化 | 硬编码中文 | `Localizable.xcstrings`（String Catalog），zh-Hans 与 en；`InfoPlist.xcstrings`（权限用途说明）；App 内语言切换 |
| 内购 / 商店 | 只有中文 | 英文商品名和描述（App Store Connect 本地化），StoreKit 显示价格本来就本地化；`docs/appstore/en/` |
| UI 测试 | 只测中文 | 中英两种 locale 都跑（`-AppleLanguages (en)`），并检查有没有漏翻的中文 |

## 2. 分阶段（每阶段一个提交 / 一轮 Mac 运行）

### P1 数据模型：每方各自的语言（不改界面）
- `PartyLanguage`、`Conversation(myLang:, theirLang:)`，`Lang.tourist` 改为默认值；`LanguageGuess` 扩展到 zh/id/en（按汉字比例 + 印尼语/英语词表）。
- `Transcript` 和 `Money` 按 `viewer.lang` 输出；翻译路由函数 `route(from:to:)` → `.same` / `.appleTranslation` / `.understand(tgt)`。
- **测试（Linux）**：9 种语言组合的路由表、同语直通、语言猜测（每种语言 20 条样例 + 混写）、原有 118 项不退化。
- **Mac**：编译 + 现有 UI 测试全绿（界面上不应有任何变化）。

### P2 金额：英文解析与按查看者加注
- `AmountParser` 增加英文写法；`FXFormatter` 支持目标 Rp（印尼语查看者），`annotateEnglish`。
- 币种来源由「系统语言」改为「我方语言」（设置里可以手动指定）。
- **测试**：英文写法表（k/thousand/million/m/bn、`IDR`/`Rp`/`rupiah`/`$`）、2000 次随机数量级属性测试扩展到英文输出、白名单测试（模型写错数量级时不加注）、USD/CNY/IDR 三种目标。
- **Mac**：截图 `08_amount_conversion_en`（英文查看者 ≈ $）。

### P3 提示词与校验参数化（仍用 s400）
- `PromptBuilder(src:, tgt:)`；few-shot 分 zh 和 en 两组；`Validator` 支持英文输出。
- 理解只在「对方 id/口语 → 我方 zh 或 en」时启用，其余方向走 Apple Translation 直译。
- **测试**：提示词快照（每个方向一份）、英文校验用例（金额错误必须被拒）。
- **评测（盒子 CPU 冒烟 + Mac）**：用 s400 原样跑新的 App 格式 id→en 60 条（新建 `eval_appfmt_en`），作为「不重训」的基线。

### P4 对话与面对面界面：语言选择
- 顶栏「我说 ▾ / 对方说 ▾ / ⇄」；面对面两半屏各自的语言按钮；`HoldToTalk` 按说话方选 locale；`Readiness` 按语言对显示缺哪些语言包。
- **测试**：`ConversationModel` 切换语言后已有消息不重译，只影响新消息；`UITestMode` 新增 `mock-ready-en-partner` 等启动参数。
- **Mac**：UI 测试新增「对方英语、我方中文」「对方中文、我方英语」两条完整对话，截图 10_lang_picker、11_face_to_face_lang。

### P5 Apple Translation 六个方向与离线语言包引导
- 引导页按「我方 + 对方」两种语言列出需要的语言包；不支持的语言对给出明确提示；降级顺序：Apple → 本地模型（只有 →zh/→en 的理解）→ 只能用常用句。
- **测试**：`Readiness` 按语言对的组合表测试。
- **Mac 和真机**：模拟器上 id/en 语言包不可用（r4 已见），**必须真机**验证六个方向离线可用。

### P6 常用句 / 场景三语
- `PhraseText{zh,id,en}` 全量补齐英文表达（按英语母语习惯重写），场景名称和副标题三语。
- 印尼语常用句沿用 `docs/印尼语短语核对.md`；英文版新增「待英语母语复核」清单。
- **测试**：每句三语都不为空、礼貌称呼规则（id）、长度上限（出示页）、和 FLORES 测试集没有重合。
- **Mac**：截图常用句中英两版。

### P7 界面国际化（String Catalog）
- 把 `Copy.*`、所有 `Text("…")`、按钮、错误、`accessibilityLabel`、通知、权限用途说明抽取到 `Localizable.xcstrings`（Xcode 编译时自动提取；Linux 上用脚本检查 key 有没有遗漏）。
- TripAppModel 里面向用户的文案改为返回 `LocalizedStringResource` / key，不再直接返回中文。
- App 内切换语言：设置 →「界面语言：跟随系统 / 中文 / English」（写入 `AppleLanguages`，重启生效，或用 SwiftUI `\.locale` 环境）。
- **测试**：Linux 脚本 `scripts/check_strings.py`：xcstrings 每个 key 必须有 zh-Hans 和 en，代码里不能残留中文字面量（白名单除外）；UI 测试在 `-AppleLanguages (en)` 下跑全套，并断言没有中文字符（常用句里的中文对照除外）。
- **Mac**：中英两套全量截图（01–11），检查英文文案溢出和截断。

### P8 内购 / 商店英文材料

## 3. 是否需要重训 s400
- **id→zh**：不需要（已采用）。
- **id→en 理解**：s400 没有训练过 id→en 的理解格式。先在 P3 用 s400 原样跑 `eval_appfmt_en`：
  - 达到 §5 规则 → 不重训，直接上线；
  - 不达标 → P9 重训一个 v2 适配器（数据：场景 id→zh + 新的 id→en 场景 + 三语回放）。
- **zh↔en / en↔id / zh→id**：**默认交给 Apple Translation**，本地模型不承担，所以 s400 不必为这些方向重训；只评测「降级时用本地模型直译」的质量，作参考。

## 5. 评测与按方向采用规则
- FLORES devtest 每个方向 n≥200（同一批句子的三语对齐）：zh→id、id→zh、en→id、id→en、zh→en、en→zh，chrF++（目标为中文时用 chrF char）。
- App 格式：`eval_appfmt`（id→zh，60 条）+ `eval_appfmt_en`（id→en，新建 60 条，含金额题）。
- **采用规则（每个方向单独判定）**，以同机基座为准：
  - 由本地模型承担理解的方向（id→zh、id→en）：App strict ≥ 基座 + 10；金额错 ≤ 基座；
  - 所有六个方向：FLORES chrF 下降 ≤ 10（相对同机基座）；
  - 某个方向不达标时，该方向在 App 里**不启用本地模型**，改走 Apple Translation（或回退到基座模型），不影响其他方向上线。
- 报告表格：每个方向 × 每个检查点写 ✓/✗。

## 7. 风险
1. **1.5B 模型的 zh↔en 质量**：小模型的中英互译在长句和习语上明显弱于 Apple Translation；所以默认走 Apple，本地模型只做 id 口语理解。若用户的设备不支持某个 Apple 语言对，降级后质量会下降，需要在界面上标注「低质量离线模式」。
2. **组合爆炸**：3×3 种语言组合 × 两种界面语言 × 面对面模式，UI 测试时间会翻倍；只挑代表组合跑 UI 测试，路由逻辑靠单元测试全覆盖。
3. **金额**：英文写法有歧义（「1.5k」「5 mil」、美元和印尼盾混写），必须坚持「只给原文解析出的值加注」；绝不让模型算钱。
4. **英文常用句**：直译中文语境会显得怪；需要英语母语复核，印尼语仍需印尼母语复核。
5. **字符串抽取**：TripAppModel 是纯 Swift 包，Linux 上没有 String Catalog 工具链；用 key + 资源包 + 脚本校验，避免在 Linux 上测不了。
6. **商店审核**：英文版描述不能承诺「所有语言对都离线可用」，要写明需要下载 Apple 语言包、支持的设备。
7. **工作量**：P1–P8 大约 8 轮 Mac 运行；P9 训练再加一轮（约 2.5 小时训练 + 评测）。
