## 2. 设备档位与支持判定

```swift
enum DeviceTier: String { case a8GB, b6GB, c4GB, unsupported }
```

- 判定：`ProcessInfo.processInfo.physicalMemory`。≥7.5 GB 为 A，≥5.5 GB 为 B，≥3.5 GB 为 C，否则不支持。
- C 档默认 `unsupported`，直到 §19.3 实验通过后，通过发布新版本打开（不做远程开关）。
- 商店层面：Info.plist 的 `UIRequiredDeviceCapabilities` 可以考虑加入能排除旧机型的能力项（需核实是否有合适的项）；同时可以考虑 Increased Memory Limit entitlement（需核实适用范围和审核要求）。两者都在 §20 第 0 步验证。
- 不支持的设备：首次启动显示 PRD v2 的「这台 iPhone 内存不足，暂不支持」，不提供下载和购买。

## 3. 总体结构

```
对话界面 / 准备页 / 阻断 sheet
   │
   ▼
ReadinessGate            启动、回到前台检查全部必备项；不完整则阻断
TurnCoordinator          一场里产生一条消息的唯一入口
   │
   ├── SessionStore
   ├── NumberNormalizer   金额与数字规则（纯代码）
   ├── Glossary           词表与缩写展开
   ├── Translator         系统离线翻译
   ├── Speaker            系统离线听写；印尼语可替换实现
   ├── Understander       端侧理解模型（必备）
   ├── Entitlement        买断与试用（钥匙串）
   ├── ModelDownloader    自有资源下载、校验、安装
   ├── PrepareStatus      五项就绪状态
   └── Metrics            匿名本机计数（可关闭）
```

依赖只自上而下；`Translator`、`Speaker`、`Understander` 互相不引用。

## 5. 数字与词表（纯代码，模型前）

### 5.1 金额规则

在印尼语原文上执行，大小写不敏感，长匹配优先：

| 形式 | 倍数 |
| --- | --- |
| `(\d+(?:[.,]\d+)?)\s*(rb|ribu|rbu)\b` | ×1,000 |
| `(\d+(?:[.,]\d+)?)\s*(jt|juta)\b` | ×1,000,000 |
| `(\d{1,3}(?:\.\d{3})+)`（如 `50.000`、`1.500.000`） | 点是千分位，直接按整数 |
| `\d+k\b`（英文） | ×1,000 |

- 带单位时，逗号和单个点按小数处理：`1,5jt` = 1,500,000；`2.5jt` = 2,500,000。
- 不带单位的纯 2～3 位数（如 `40`、`175`）：**不在代码层换算**，交给理解模型结合上下文判断（本场已出现过 rb/ribu 等金额时，提示模型「可能是千」）。
- 换算结果用中文表示：能被 10,000 整除写「{n}万」；否则写到一位小数的「{x}万」（如 17.5 万）；小于 10,000 写阿拉伯数字。币种不写。

### 5.2 占位与回填

1. 原文中命中的金额替换成占位符 `⟦N1⟧`、`⟦N2⟧`，记录 `{N1: "5万"}`。
2. 把带占位的文本送系统翻译；翻译后把 `⟦Nk⟧` 回填成中文金额。
3. 占位符在译文里丢失或重复时，丢弃这次占位，改用原文直接翻译，再在字面中文后面追加「（{金额}）」。
4. 理解模型的输入同时给原文和已经换算的金额表。

### 5.3 金额校验（模型后）

理解模型输出里出现的「X万」和阿拉伯数字，必须能在「代码换算表 ∪ 原文数字 ×1 ∪ 原文数字 ×1000（仅本场已有金额上下文时）」里找到；否则判为不合格，主行保持字面。

### 5.4 词表与缩写

- `glossary-id.json` 增加 `kind`：`term`（词条）或 `abbr`（缩写，如 `brp→berapa`、`gk→tidak`、`udh→sudah`、`bs→bisa`、`sy→saya`、`otw→在路上`、`mnt→menit`、`lg→lagi`）。
- 缩写在送系统翻译前展开（改善字面），并作为词表命中传给模型（≤8 条）。
- 来源：公开语料、志愿者造句、母语者校对；**不使用未经授权的真实私聊**。上线前规模 ≥300 条。

## 6. 翻译

同 1.1 第 6 节：`Translation` 框架，四个方向（`id↔zh-Hans`、`en↔zh-Hans`），超时 2.0 秒。改动：

- 删除「不许去掉 on-device 限制重试」的表述（系统翻译本身是本机翻译）；改为 §17 的「推理路径网络零请求」测试。
- 就绪检查用 `LanguageAvailability`，语言包未安装由 `ReadinessGate` 阻断，不再在对话中产生 `packMissing`。
- 系统语言包下载走系统界面（`prepareTranslation` 一类 API，具体以 iOS 26 SDK 为准）；应用无法强制 Wi‑Fi，也不显示大小（不承诺）。

### 6.1 回译

同 1.1 §6.2，改动：

- 一致判定以关键信息为主：数字 / 金额集合一致，否定词（不、没、别）一致；再以字符重合率 ≥ 阈值（初值 0.6，用真实样本校准）为辅。
- `forceShowBackTranslation == true`（我的消息被理解模型改写）时，无论是否一致都显示。

## 7. 听写

同 1.1 第 7 节，改动：

- 录音格式：使用 `SpeechAnalyzer.bestAvailableAudioFormat(...)`（或框架等价接口）返回的格式；`SFSpeechRecognizer` 路径用 `AVAudioEngine` 输入节点格式，不写死 16 kHz。
- 「`SpeechTranscriber` 在进程外运行、不计内存」作为假设，在 §19 用 Memory Report 验证。
- 印尼语实验（1.1 §7.3）**提前到 §20 第 0 步**。三种结论：系统可离线 → 系统实现；系统不行但备用包达标 → `IndonesianLocalSpeaker`，作为准备项第 4 行；都不行 → 准备页固定「听印尼语暂不可用」，**不阻断**（PRD v2 §4.1 例外）。
- 备用听写包与理解模型的内存关系：A/B 档可以同时常驻（以 §8.5 预算为准）；C 档必须互斥，先卸载理解模型。

## 8. 理解模型 `Understander`（必备）

### 8.1 职责

1. **对方消息**：输入上下文 + 原文 + 金额表 + 词表命中 + 字面中文 → 一行中文（游客读的主行）。
2. **我的消息**：游客中文含指代（正则来自 `Resources/reference-zh.json`）且本场有上下文时 → 输出「要翻译的中文」。金额 / 数字必须与游客原文一致，否则丢弃改写。
3. 每一句都调用（对方消息），只有两种情况不调用：试用已用尽；这一句是纯数字。（1.1 的「没有上下文且词表没命中就不跑」取消：缩写和俚语在第一句就需要理解。）

### 8.2 提示词与接口

```text
[system]
你是旅行对话的中文译文修正器。游客是中国人，对方说{对方语言}。只修改「字面」这句中文，让它符合这场对话和原文真实意思。
规则：缩写俚语译对；金额用给出的换算表，不要自己换算；讲价上下文里没有单位的数字可能是「千」，写成「万」；把指代说清楚；不要写外语单词，不要解释；只输出一行中文。
[few-shot ×2～3，固定]
[user]
这场对话（时间顺序）：
对方：{原文} ／ 中文：{展示句}
我：{中文}
…
金额：{⟦N1⟧=5万, …｜无}
词：{source = zh, …｜无}
对方原文：{原文}
字面：
{zhLiteral}
```

- 系统提示和少样本部分在模型加载后**预先计算 KV 并缓存**；每句只 prefill 上下文和当前句。
- 采样：温度 0（贪心），最多 64 token，遇到换行停止。
- 输出校验：取第一行，去掉引号和空白；空、超过 80 个汉字、含 ≥4 个连续拉丁字母（金额表外的品牌和地名，如 `QRIS`、`sunset road`，允许出现在原文里有的词）、金额校验失败（§5.3）→ 不合格，保持字面。
- 规范化后与字面相同 → `zhDidUnderstand = false`，不替换。

### 8.3 模型清单（按档位）

`Resources/model-manifest.json`（打进安装包，随版本更新）：

```json
{
  "version": 2,
  "models": [
    {"tier": "a8GB", "id": "understand-1.7b-q4km-v1", "url": "https://…", "bytes": 0, "sha256": "…", "ctx": 2048, "promptVersion": 1},
    {"tier": "b6GB", "id": "understand-1.7b-q4km-v1", "url": "https://…", "bytes": 0, "sha256": "…", "ctx": 2048, "promptVersion": 1},
    {"tier": "c4GB", "id": "understand-0.6b-q4km-v1", "url": "https://…", "bytes": 0, "sha256": "…", "ctx": 1536, "promptVersion": 1}
  ]
}
```

- 基础模型：Qwen2.5-1.5B-Instruct 或 Qwen3-1.7B（验证报告 §5.1，二选一取决于微调和真机结果），**LoRA 微调后合并再量化为 Q4_K_M**，约 1.1GB。
- C 档：1.5B Q4_K_M 与微调后 0.5B～0.6B 两个候选，按 §19.3 实验决定；都不达标则 C 档不支持。
- 4B 不作为默认（验证报告：iPhone 上发热降速）；A 档只有真机满足 §9 预算才考虑。
- 微调数据、评估集、通过线见验证报告 §5.4（严格分 ≥85%，金额错误为 0）。

### 8.4 运行时

- llama.cpp iOS 构建，Metal，GGUF，放在 `Understander` actor，不在主线程 decode。
- §20 第 0 步与 MLX Swift 做 A/B（速度、峰值内存、冷加载），结论写进 `docs/runtime-ab.md`。
- **Apple Foundation Models 可选加速**：设备支持、`SystemLanguageModel.default.availability == .available`，且离线评估集上质量达标时，A 档可以优先用系统模型。系统模型不可用时（例如中国大陆购买的设备），必须使用已下载的自有模型。**自有模型在所有档位都必须下载**，因为系统模型可用性受区域和设置影响，随时可能变化（验证报告 §3）。

### 8.5 内存

| 项 | A 档预算 | B 档预算 | C 档预算 |
|---|---|---|---|
| 理解模型权重（mmap） | ≤1.5GB | ≤1.2GB | ≤0.5～1.1GB |
| KV 缓存（ctx 2048 / 1536） | ≤250MB | ≤250MB | ≤150MB |
| 应用其余（UI、会话、音频） | ≤200MB | ≤200MB | ≤150MB |
| 备用印尼语听写包 | 可共存 | 可共存（真机验证） | 必须与模型互斥 |

- 启动后、准备完成时预热加载；常驻。
- `didReceiveMemoryWarning`：先释放 KV 缓存，再次警告卸载权重；下一句重新加载（本句保持字面）。
- 进入后台：释放 KV 缓存，保留 mmap 权重。
- 出现 jetsam 即视为测试失败。

## 9. 延迟预算与流式

从 `Turn.createdAt` 起算（对方消息）：

| 段 | 预算 |
|---|---|
| 金额规则 + 缩写展开 | ≤20ms |
| 系统翻译出字面 | ≤1.0s（上限 2.0s） |
| 理解模型 prefill（只算增量） | ≤0.8s |
| 生成 ≤64 token（常见 15～25） | ≤0.8s |
| 校验 + 替换 | ≤20ms |
| **合计** | **≤3.0s（P90）**，超时固定字面 |

- 为了不等字面：理解模型和系统翻译**并行启动**；如果理解结果先到，等字面上屏后再替换（保证「字面先上屏」）。
- 流式：token 流式进入缓冲区，到换行或结束后整体校验，通过再一次性替换主行，界面不逐字刷新。
- 我的消息：理解改写最多等 1.0s，超时用原文翻译。
- 冷加载（首次或被卸载后）：不计入单句预算，单独打点；目标 ≤2s（A/B 档）。

## 10. 一条消息的时序

### 10.1 对方（`submitThem`）

1. 试用用尽：只做字面，不调用理解模型，不计数。
2. 语言：默认开关；§11 猜测为另一种语言时设置 `offerRetranslateAs`。
3. 写入 `Turn(status: .translating)`，原文立即可见。
4. 金额与缩写处理（§5），得到 `textForMT` 和金额表。
5. 并行：`Translator.translate` 与 `Understander.understand`（理解模型输入需要字面，故在字面到达后再提交 prompt；prefill 系统部分已缓存，所以「并行」指的是模型准备和上下文 prefill 先做）。
6. 字面成功：写入 `zhLiteral`、`zhDisplay`，`status = .ready`，计数 +1。
7. 理解结果在 3 秒内通过校验：写入 `zhDisplay`，`zhDidUnderstand = true`。
8. 翻译失败：`status = .failed`，不计数。

### 10.2 我（`submitMe`）

1. 校验汉字或纯数字。
2. **试用用尽**：创建 `Turn(status: .trialBlocked, trialBlocked: true)`，只有中文主行，界面显示用尽提示句。不翻译，不计数。
3. 创建 `Turn(.translating)`。
4. 纯数字：原样作为 `foreignText`，计数 +1。
5. 含指代且本场有上下文：调用理解模型（≤1.0s），金额校验通过则 `understoodTextForMT = 输出`，`forceShowBackTranslation = true`；否则用原文。
6. 翻译到 `theirLanguage`（2s 超时）。成功写入 `foreignText`，计数 +1；随后异步回译。
7. 失败：中文气泡保留，`status = .failed`。

### 10.3 重译、消息锁

重译同 1.1 §9.3。消息锁：只有 `status == .translating` 的消息存在时禁用发送和按住；理解模型的后台任务不占锁。

## 12. 剪贴板

- `scenePhase == .active` 时只调 `UIPasteboard.general.hasStrings`（不读取内容，不触发系统粘贴授权；以真机为准）。
- 有文字时显示提示条（不显示内容）。用户点击时通过系统粘贴控件（SwiftUI `PasteButton` 或 `UIPasteControl`）读取，这是用户主动粘贴，不额外弹授权。
- 读取后与最后一条 `sourceText` 比较；相同则提示「这句已经在对话里了」。
- 截断到 500 字；剪贴板内容不进日志。
- 若真机上 `hasStrings` 也会触发授权，则改为「只在用户点输入框旁的粘贴按钮时读取」，提示条取消。

## 13. 离线准备、下载与阻断

### 13.1 必备项

```swift
struct PrepareStatus: Equatable {
    var touristSpeech: Readiness           // zh-CN 听写
    var theirLanguages: [TheirLanguageReadiness] // 每门：translation、speech
    var understander: Readiness            // 理解模型
    var isComplete: Bool                   // 除「印尼语听写 unavailable」外全部 ready
}

enum Readiness: Equatable {
    case ready, checking, needsDownload(bytes: Int64?)
    case downloading(progress: Double), paused(progress: Double)
    case notEnoughSpace(needed: Int64?), verifyFailed
    case unavailable(String)               // 只用于印尼语听写的「暂不可用」
}
```

### 13.2 `ReadinessGate`

- 触发：冷启动、`scenePhase` 变为 `.active`、下载完成、收到 `NSBundle` 资源或系统语言包变化通知（若有）。
- 检查：系统翻译四个方向 `LanguageAvailability`；听写 `availability`；理解模型文件存在 + 大小一致 + 记录的 SHA‑256 一致（完整哈希只在安装时计算；启动时检查大小和安装标记文件，每周或文件修改时间变化时重新校验完整哈希）。
- 结果不完整：对话页呈现**不可下滑关闭**的阻断 sheet（PRD v2 §4.4）。下载进行中则直接显示准备页进度。
- 检查不阻塞首帧：先显示上次的对话（只读）和骨架，100～300ms 内给出结论。

### 13.3 `ModelDownloader`

- `URLSessionConfiguration.background(withIdentifier:)`，支持应用被挂起时继续下载。
- Wi‑Fi 策略：默认 `allowsCellularAccess = false`、`allowsExpensiveNetworkAccess = false`；用户在蜂窝确认后，对这次任务设为 true。
- 断点续传：保存 resume data；HTTP Range 支持（CDN 必须支持）。resume data 失效时从已下字节用 Range 继续；仍失败从头。
- 空间预检：`volumeAvailableCapacityForImportantUsage` ≥ 文件大小 × 1.1；不足返回 `notEnoughSpace(needed:)`。
- 校验：下载完成后计算 SHA‑256，与清单一致后**原子安装**：移动到 `Application Support/models/{id}/model.gguf`，写入 `installed.json`（id、bytes、sha256、时间），文件设 `isExcludedFromBackup = true`。不一致：删除，自动重试 1 次，再失败为 `verifyFailed`。
- 存储位置不能是 `Caches`（系统可能清理）。
- 版本迁移：新版本清单的 `id` 变化时，默认需要阻断并下载新模型（PRD v2 §4.5），新模型就绪后删除旧模型。若新旧模型 `promptVersion` 兼容，清单可以标记 `compatibleWith` 允许旧模型继续使用（避免每次更新都阻断）。
- 下载来源：HTTPS，固定域名；清单打进安装包，不从网络获取清单（避免篡改）。
- 成本：CDN 流量约「模型大小 × 安装次数 × 1.1（重试）」，上线前按预期装机量估算预算。

### 13.4 首次启动流程

1. `DeviceTier` 判定；不支持 → 不支持页。
2. 引导页（PRD v2 §4.3）。「全部准备」依次：系统翻译四方向（系统界面）→ 中文、英文听写（系统）→ 印尼语听写实验结论对应的项 → 理解模型（`ModelDownloader`）。系统项和模型下载并行。
3. 全部就绪 → 预热理解模型 → 进入对话页。
4. 引导期间可进入：隐私说明、购买 / 恢复购买、示例演示页（内置预录的输入输出文本，不调用模型；审核需要）。

### 13.5 模型托管与分发（多镜像）

**结论：自建「对象存储 + CDN」，国内镜像 + 海外镜像双线，清单驱动；不内置进安装包；Apple 托管的 Background Assets 作为后续可选项。**

背景：Hugging Face 在中国大陆基本不可直连，而我们的用户是出发前在国内首次打开 App 下载约 1.1 GB 模型（必备、阻断式）。只靠 HF 等于大部分用户卡在首启。

| 镜像（清单顺序） | 建议 | 说明 |
|---|---|---|
| 1. `cn` 国内 | 阿里云 OSS + 阿里云 CDN，或腾讯云 COS + 腾讯云 CDN | 国内下载主力。CDN 加速域名需 ICP 备案（上线前要留出备案时间） |
| 2. `global` 海外 | Cloudflare R2（自定义域名，走 Cloudflare CDN） | 已在印尼/海外的用户、国内线路异常时兜底；R2 无出网流量费 |
| 3. `hf` 占位 | Hugging Face 固定 commit 的 resolve 地址 | 目前唯一真实可下的地址，真实镜像就绪前保留；就绪后放最后一位或删除 |

**地址与完整性**
- 对象路径带版本且不可变：`models/{model}/{quant}/{sha256前8位}/{file}.gguf`；新模型 = 新路径，永不覆盖旧对象，CDN 可设长缓存（`Cache-Control: public, max-age=31536000, immutable`），也避免「半更新」。
- 所有镜像同一文件、同一 `sha256` 和 `bytes`；客户端下载完必须整文件 SHA-256 校验（§13.3），镜像本身不被信任。
- 签名 URL：OSS/COS 用 URL 签名 + CDN 鉴权（如阿里云 CDN 鉴权 A/B/C 类型、腾讯云 CDN 鉴权），R2 用 Cloudflare 的签名/Token 规则或 Worker 校验，主要用于防盗链和防刷流量；签名有效期要覆盖后台下载 + 续传（建议 ≥ 24 小时），过期后由 App 重新请求清单换新签名。Demo 阶段用公开只读地址。
- 必须支持 `Range` 请求（续传依赖），并保证同一对象 `ETag` 稳定。

**清单驱动更新（不发版）**
- 安装包内置 `model-manifest.json`（离线首启可用的兜底）；上线后可再加一个远程清单（同样放在两条镜像上，带签名或固定公钥校验），App 启动有网时拉取，只用于：换镜像地址、调整镜像顺序、发布新模型版本（新 `id`/`sha256`/路径）。
- 新模型版本：后台下载新文件 → 校验 → 原子替换 → 删旧；未完成前继续用旧模型，不触发阻断（阻断只针对「本机没有任何可用模型」）。
- 远程清单拉取失败时一律回落到内置清单，绝不阻断。

**客户端多镜像策略（已实现：`MirrorSelector` + `ModelDownloader`，测试见 `MirrorTests`）**
- 按清单顺序从第一个镜像开始；无 resume data 的失败立即换下一个；有 resume data 时在同一镜像续传，同一镜像连续失败 2 次再换。
- 过慢切换：开始 10 秒后，最近 20 秒平均速度 < 150 KB/s 且还有没试过的镜像时，暂停拿到 resume data 后切下一个；已因过慢跳过的镜像本轮不再切回，避免来回跳。
- 续传只在**产生它的镜像**上使用（resume data 里带着原 URL 与校验信息，跨主机续传不安全）；切到别的镜像从 0 开始，原镜像的 resume data 保留，切回时还能续。
- 校验失败视为该镜像内容有问题，状态机自动重下的那一次走下一个镜像。
- 一轮所有镜像都失败后停下，显示「下载失败，重试」；用户点重试开始新一轮（从首选镜像开始）。

**成本（估算，按公开价目粗算，未含税和阶梯优惠，上线前按实际报价复核）**
- 每次完整下载约 1.1 GB。1 万次完整下载 ≈ 11 TB 流量。
- 国内 CDN 下行约 ¥0.15–0.25/GB（按量，量大更低）→ 1 万次约 ¥1,700–2,800；对象存储本身几 GB，存储费可忽略；回源流量另计但有 CDN 缓存后很小。
- Cloudflare R2：存储约 $0.015/GB·月，出网流量免费，按请求次数计费（少量）→ 海外线路基本只有存储费。
- 防刷：签名 URL + 单 IP 限速/限次、CDN 用量告警与封顶，避免被盗链刷出高额账单。

**替代方案：Apple Background Assets / On-Demand Resources**
- Managed Background Assets（iOS 26+）：系统管理下载、更新与压缩，可在安装时（Essential）就下载；Apple 托管时每个 App 最多 200 GB、最多 200 个资产包，资产包可单独上传，更新不必发版。来源：[Overview of Apple-hosted asset packs](https://developer.apple.com/help/app-store-connect/manage-asset-packs/overview-of-apple-hosted-asset-packs)、[Apple-hosted asset pack size limits](https://developer.apple.com/help/app-store-connect/reference/app-uploads/apple-hosted-asset-pack-size-limits/)、[WWDC25「Discover Apple-Hosted Background Assets」](https://developer.apple.com/videos/play/wwdc2025/325/)。
  - 限制：要求 iOS 26+（我们最低 iOS 17）；Apple 工程师在论坛说明同一 App 不能同时用 Apple 托管和自建托管的 Background Assets 功能，Managed 与非 Managed 也不能混用（[Developer Forums 827100](https://developer.apple.com/forums/thread/827100)）；国内下载体验依赖 Apple CDN，无法自己控制镜像与切换。
  - 定位：后续若最低版本提到 iOS 26，可评估改成「Essential 资产包随安装一起下载」，首启阻断时间会更短；当前不采用。
- On-Demand Resources：WWDC25 已说明由 Managed Background Assets 取代（ODR 已弃用）。限制见 [On-demand resources size limits](https://developer.apple.com/help/app-store-connect/reference/app-uploads/on-demand-resources-size-limits/)：iOS 18 以下单个资产包 512 MB（模型约 1.1 GB 需拆包），iOS 18+ 单包 8 GB、托管总量 70 GB。弃用技术不作为新项目方案。

**为什么不内置进安装包**
- 1.1 GB 模型打进 IPA：所有用户（包括只看看的用户）都要下大包；App Store 蜂窝下载对大包有提示/限制，转化率下降。
- 4 GB/6 GB/8 GB 设备分档（§4）需要不同模型，内置只能全打或打最大，浪费空间。
- 模型迭代（LoRA 新版本）必须发版过审，无法按清单快速回滚。
- 系统翻译语言包本来就要首启下载（Translation / Speech 资源由系统管理），内置模型也省不掉首启下载步骤。

## 17. 隐私实现

- 推理路径网络零请求：真机飞行模式和有网环境分别用网络调试仪表 / 代理确认，对话过程中**没有任何连接**（下载、StoreKit、匿名计数除外）。代码审查清单加一条：`Translator`、`Speaker`、`Understander` 模块不得引用 `URLSession`。
- 匿名计数 `Metrics`：只有计数和耗时分桶（PRD v2 §15.2），本机聚合，每天最多上报一次，用户可在隐私说明里关闭；关闭后不上报，本机数据删除。若产品决定不上报，则此模块只保留本机计数。
- 文件保护：会话、试用、模型安装记录使用 `completeUntilFirstUserAuthentication`（保证后台回来能写）；会话和计数排除备份。
- 隐私清单 `PrivacyInfo.xcprivacy`：声明用到的 Required Reason API（UserDefaults、文件时间戳、磁盘空间），以及（若上报）匿名使用数据。
- 麦克风文案按 PRD v2 §12 修改。
- 不集成第三方统计或崩溃 SDK。

## 金额换算实现（FX，2026-10-12）

- `TripCore/FX.swift`：`TargetCurrency`（按 `Locale.preferredLanguages` 选 CNY/USD）、`FXRates`（bundled + `isSane` ±30% + `parseFrankfurter`）、`FXFormatter`（<10 保留一位小数，否则取整加千分位，区间「约 ¥11–15」）、`AmountAnnotator`（`annotateSource` / `annotateChinese` 白名单=原文解析值）、`CNYParser`（¥/元/块/人民币/万 → `约 Rp 536.000`）。
- `Amount.swift` 新增 `prefixedRegex`（Rp/IDR + 分组整数，后面无单位时才匹配）。
- `TripAppModel/FXStore.swift`：UserDefaults 缓存、`shouldRefresh`（在线且距上次尝试 ≥6h）、`refresh` → updated/rejected/failed/skipped；`FXContext.caption` / `isStale`（30 天）。
- `Transcript.rows(..., fx:)` 仅对 viewer=.me 加注；对方视角（给对方看的屏）不加注。
- 刷新接口：`https://api.frankfurter.dev/v1/latest?from=USD&symbols=IDR,CNY`，10 s 超时；UITestMode 下禁用刷新、固定内置汇率 + CNY。
- 测试：`FXTests`（含 2000 次随机数量级属性测试）、`FXStoreTests`、`UITestSeedAmountTests`；XCUITest `testAmountConversionShown`（`-UITestSeedAmount`）。
