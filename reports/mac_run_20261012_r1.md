### 1. `App/TripApp/Speech.swift`（以及同类的 `SystemServices.swift`）

报错原文（`xcodebuild -destination 'generic/platform=iOS'`，第一次）：

```
App/TripApp/Speech.swift:86:13: error: cannot find 'SpeechTranscriber' in scope
App/TripApp/Speech.swift:87:22: error: cannot find 'SpeechTranscriber' in scope
App/TripApp/Speech.swift:88:28: error: cannot infer contextual base in reference to member 'bcp47'
App/TripApp/Speech.swift:90:33: error: cannot find 'SpeechTranscriber' in scope
App/TripApp/Speech.swift:90:60: error: cannot infer contextual base in reference to member 'progressiveTranscription'
App/TripApp/Speech.swift:91:24: error: cannot find 'SpeechAnalyzer' in scope
App/TripApp/Speech.swift:92:35: error: cannot find 'SpeechAnalyzer' in scope
App/TripApp/Speech.swift:94:24: error: cannot find 'AnalyzerInput' in scope
App/TripApp/Speech.swift:107:25: error: cannot find 'AnalyzerInput' in scope
```

原因：Xcode 16.2 的 iOS 18.2 SDK 里没有 `SpeechAnalyzer` / `SpeechTranscriber` / `AnalyzerInput`（Speech 框架里只有 `SFSpeechAnalyzer`）。`@available(iOS 26.0, *)` 挡不住旧 SDK 的类型检查。`SystemServices.swift` 里同样调用了 `SpeechTranscriber`、`AssetInventory`，以及 iOS 18 的 `Translation.swiftinterface` 里不存在的 `TranslationSession(installedSource:target:)`。第一次编译在 `Speech.swift` 处停下，这些符号没有单独打出 error 行；按同一原因在编译下一轮之前包进了条件编译。包上之后，下一次真机编译不再报这些符号。

改动：用 `#if compiler(>=6.2)` 包住 iOS 26 路径。当前 Swift 6.0.3 会走原来的 `SFSpeechRecognizer` 和 iOS 18 `translationTask`。

- `Speech.swift` 第 32–34 行：调用 `startAnalyzer` 的那一行。
- `Speech.swift` 第 88–136 行：整个 `startAnalyzer`。
- `SystemServices.swift` 第 30–35 行：`speechReadiness` 里的 `SpeechTranscriber`。
- `SystemServices.swift` 第 50–56 行：`install` 里的 `SpeechTranscriber` / `AssetInventory`。
- `SystemServices.swift` 第 68–73 行：`TranslationSession(installedSource:target:)`。

### 2. `App/TripApp/AppState.swift`

报错原文（源码修复后的第二次真机编译）：

```
App/TripApp/AppState.swift:88:41: error: variable 'self.talk' used before being initialized
        conversation.onChange = { [weak self] in self?.tick += 1 }
                                        ^
```

原因：Swift 6 的确定初始化。闭包捕获 `self` 时，`let talk` 和 `let sessions` 还没赋值。

改动：先完成 `talk = HoldToTalk(...)` 和 `self.sessions = sessions`，再给 `conversation.onChange` 和 `talk.onChange` 赋值。闭包体没变。现在这两行在第 91–92 行。

### 3. 模拟器链接：llama.xcframework 没有模拟器切片（未改仓库里的二进制）

报错原文（第一次模拟器 `xcodebuild`）：

```
error: While building for iOS Simulator, no library for this platform was found in '/Users/xianghaiquan/trip-work/DerivedData/SourcePackages/artifacts/tripcore/llama/llama.xcframework'. (in target 'TripLLM' from project 'TripCore')
error: While building for iOS Simulator, no library for this platform was found in '/Users/xianghaiquan/trip-work/DerivedData/SourcePackages/artifacts/tripcore/llama/llama.xcframework'. (in target 'TripUnderstand' from project 'TripUnderstand')
```

原因：官方 b11541 的 `llama-b11541-xcframework.zip` 解出来只有 `macos-arm64_x86_64` 和 `ios-arm64`。`vtool` 显示 `ios-arm64` 的 platform 是 `IOS`，不是 `IOSSIMULATOR`，不能拿来冒充模拟器库。checksum 与 `Package.swift` 一致，没有改 checksum，也没有把库提交进 git。

本机处理（不在 diff 里）：用 llama.cpp `b11541`（`f2918ca`）按 `build-xcframework.sh` 的 iOS Simulator 参数编了 arm64 模拟器 dylib（`GGML_METAL=ON`，最低系统 16.4），签了 ad-hoc，放进已解压的 xcframework，目录名 `ios-arm64-simulator`，并在 `Info.plist` 里加了 `SupportedPlatformVariant = simulator`。`DerivedData` 和 `DerivedData-pkg` 各补了一次，因为换 DerivedData 会重新解压官方 zip。干净机器上要重做这一步，模拟器才能链接。

`xcodegen generate` 补上了工程里原先没有的 `TripUITests` target（`DEVELOPMENT_TEAM` 为空字符串）。这是工程文件再生，不是 App 逻辑。
